# nektar++ — mesh and reference simulation

This folder contains the files needed to produce the reference flow data for the thesis: the 2D incompressible flow past a circular cylinder, simulated with the spectral/hp element framework [Nektar++](https://www.nektar.info/).

It is the first part of the thesis workflow:

```
.geo → Gmsh → mesh → NekMesh → .xml mesh → IncNavierStokesSolver → .chk → FieldConvert → .vtu → extract/
```

## Files

| File | Purpose |
|---|---|
| `*.geo` | Gmsh geometry: domain, cylinder, physical groups and mesh-size fields |
| `*.msh` / `*.xml` mesh | Mesh generated by Gmsh and converted to the Nektar++ XML format |
| `session*.xml` | Nektar++ session file: solver settings, parameters, boundary and initial conditions, output |

## Step 1 — Generate the mesh with Gmsh

The `.geo` file defines the rectangular domain with the cylinder, and the physical groups that later become the boundaries in Nektar++ (inlet, outlet, top/bottom walls, cylinder surface, fluid domain). The mesh is refined around the cylinder with boundary-layer size fields and in the wake, and is built with the Frontal-Delaunay algorithm.

```bash
gmsh -2 cylinder.geo -format msh2 -o cylinder.msh
```

`-2` creates a 2D mesh. The older `msh2` format is used because it is read reliably by NekMesh.

## Step 2 — Convert the mesh to Nektar++ format

```bash
NekMesh cylinder.msh cylinder.xml
```

NekMesh turns each Gmsh physical group into a numbered *composite* (`C[...]`). Open `cylinder.xml` and check the `<COMPOSITE>` section: NekMesh can split one physical group into several composites (for example quadrilaterals and triangles in the fluid domain). All composites that belong to the fluid must be listed in `<DOMAIN>`, and the composite IDs used in the `<BOUNDARYREGIONS>` of the session file must match the IDs in the mesh.

## Step 3 — The session file

The session file sets up the incompressible Navier–Stokes solver. Its main sections are:

- **`<SOLVERINFO>`** — equation type (unsteady Navier–Stokes), the velocity-correction scheme, time integration and dealiasing.
- **`<PARAMETERS>`** — time step, number of steps, output intervals and viscosity.
- **`<VARIABLES>`** — `u`, `v`, `p`.
- **`<BOUNDARYREGIONS>` / `<BOUNDARYCONDITIONS>`** — uniform inflow ($u = 1$, $v = 0$) at the inlet, no-slip on the cylinder, outflow at the outlet, and conditions on the top and bottom boundaries.
- **`<FUNCTION NAME="InitialConditions">`** — the starting flow field.
- **`<FILTERS>`** — checkpoint output and other run-time output.

The mesh is non-dimensional ($D = 1$, $U_\infty = 1$), so the Reynolds number is set only by the viscosity: $\mathrm{Re} = U_\infty D / \nu = 1/\nu$.

| Parameter | Re = 100 | Re = 500 |
|---|---|---|
| `Kinvis` ($\nu$) | `0.01` | `0.002` |
| `TimeStep` | `0.005` | see session file |
| `IO_CheckSteps` | `20` (one checkpoint every 0.1 time units) | see session file |

At Re = 500 the flow is less damped by viscosity, so the simulation becomes unstable without dealiasing. Dealiasing must be switched on in `<SOLVERINFO>` for this case, and the time step usually has to be smaller than at Re = 100.

## Step 4 — Run the simulation

Serial:

```bash
IncNavierStokesSolver cylinder.xml session.xml
```

Parallel with MPI (here on 8 cores):

```bash
mpirun -np 8 IncNavierStokesSolver cylinder.xml session.xml
```

The solver writes a checkpoint file (`.chk`) every `IO_CheckSteps` time steps. The first part of the run is a start-up transient before regular vortex shedding develops; these checkpoints are skipped later in `extract.py` with `CKPT_START`.

## Step 5 — Convert the checkpoints to VTU

`extract.py` reads VTU files named `cyl_chk_<number>.vtu`:

```bash
for f in *.chk; do
    FieldConvert cylinder.xml session.xml "$f" "cyl_chk_${f//[^0-9]/}.vtu"
done
```

FieldConvert can also run in parallel on large meshes (`mpirun -np 8 FieldConvert ...`). The VTU files can be opened in ParaView to look at the flow before extraction.

Then continue with [`../extract/README.md`](../extract/README.md).

## Common problems

| Problem | Cause and fix |
|---|---|
| Error about a missing or unknown composite | Composite IDs in the session file do not match the mesh. Check `<COMPOSITE>` in the mesh XML after NekMesh |
| Part of the fluid is missing in the results | Not all fluid composites are listed in `<DOMAIN>` |
| Solution blows up (NaN) at Re = 500 | Switch on dealiasing and/or reduce `TimeStep` |
| Wrong λ₂ after training | `Kinvis` in the session file and `NU` in `extract.py` do not match |

## Requirements

- [Gmsh](https://gmsh.info/)

- MPI (for parallel runs)
- [ParaView](https://www.paraview.org/) (optional, for visualisation)
